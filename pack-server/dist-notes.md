> ## ⚠️ 这个 exe 只是前端辅助工具，本身打不了包
>
> `uniapp-pack.exe` 只提供**操作界面 + 调度**：上传资源包、填参数、看进度、打开产物目录。
> **真正执行 Gradle 编译、产出 APK 的是 Docker 镜像 `uniapp-android-builder:latest`。**
>
> 所以只下载这个 exe 是不够的，你还需要：
>
> 1. 一台装了 **Docker** 的机器（本机或局域网另一台都行）
> 2. 那台机器上已有镜像 `uniapp-android-builder:latest`（约 3GB，构建方法见仓库 `android-builder/`）
>
> 缺镜像时页面会提示「打包镜像缺失 / 打包镜像不存在」，不会开始构建。
>
> 为什么这样分：DCloud 离线 SDK 受许可限制、体积 3GB+，不适合塞进 exe 一起分发。

## ⚠️ 杀毒软件报毒？是误报，处理方式在下面

如果你看到 Defender 提示 `Trojan:Win32/Sabsik.FL.A!ml`，**这是无签名 exe 的常见误报，不是真病毒**。

判定依据：`!ml` 后缀表示这是**机器学习模型推断**，不是特征库精确匹配。
触发原因通常是「未签名 + 内嵌资源 + 少人下载的新文件」，模型会倾向判为可疑。

本程序源码可完整审计（纯 Go、无下载执行、无混淆、无注入），
且构建时已改用不易触发的 `cli` 清单（`gui` 清单会稳定触发该误报）。

**三种处理方式**：

| 方式 | 操作 |
|---|---|
| 临时放行 | Defender → 保护历史记录 → 找到该条目 → 允许 |
| 加排除项 | 设置 → 病毒和威胁防护 → 排除项 → 添加这个 exe（需管理员权限） |
| **根治** | 给 exe 加代码签名（用 `signtool` 签，证书需自行购买） |

> 这类误报无法靠改代码彻底避免——同一个二进制，模型更新后也可能从「通过」变「拦截」。
> 内网使用建议统一加排除项；对外分发务必签名。

## 第一次使用

1. 双击 `uniapp-pack.exe`。首次会弹出窗口显示本机与局域网地址，可直接点「打开页面」。
2. 服务常驻右下角托盘：双击图标打开页面，右键菜单可退出。
3. 页面第一屏先「绑定打包镜像环境」（本机或远程 Docker），环境运行中后才会出现打包表单。

## 目录（都在 exe 同级，可随时备份或清理）

| 目录 | 内容 |
|---|---|
| `output` | 打出来的 APK |
| `cache` | 可再生缓存（上传包、临时文件），删了不影响配置 |
| `data` | 证书、任务记录等长期数据，删了要重新配 |

> **从旧版升级**：如果你原来的证书和记录在 exe 上一级的 `data/` 里，
> 新版会自动识别并沿用，不会丢配置。启动日志里会打印「检测到旧版数据目录…已沿用它」。

## 前置要求（重要）

需要一台**装有 Docker** 的机器，并且已有打包镜像 `uniapp-android-builder:latest`。

注意：Windows 的本机 Docker 走命名管道（npipe），本程序只支持 unix socket / TCP，
所以请把打包镜像装在一台 Linux 或局域网机器上，然后在页面里填它的 `tcp://IP:2375`。
镜像的构建方式见仓库 `android-builder/` 目录。

## 行为说明

- 同时只会运行一个实例（用命名互斥体判断，不靠端口探测）
- 端口被别的程序占用时会明确提示，不会静默失败
- 关闭弹窗不会退出，服务留在托盘继续跑；要彻底退出请用托盘右键菜单
- 界面卡住时可用 `uniapp-pack.exe --quit` 强制退出（不经过消息循环，卡死时也有效）
